**Goal:** Un-freeze the OS at its COPS driver, deliver the emulator's first live interrupts under OS code, and follow the Lisa OS's initialization (INITSYS → memory manager → scheduler → first process) as far as the evidence carries — toward the spec's M4 "desktop" north star or a documented boundary. ## Global Constraints

- Repo `~/Development/LisaEmu`; branch `m4-os-alive` from current main (`2e1fc5c`); commit per task, never amend; TDD for device/core; investigative tasks produce evidence docs; both-docs rule; strike-not-erase.
- Never commit Apple-derived data (Linkmap-DERIVED symbol tables are borderline — store parsed symbol data ONLY in-memory/from-user-supplied paths at runtime, never committed; the loader reads `~/Development/Lisa_Source/LISA_OS/Linkmaps 3.0/` or `LISAEMU_LINKMAP_DIR`); env-gating as established; one process at a time; release builds for long runs; TomHarte at close.
- Frontier facts (docs/rom-trace-notes.md "Kernel push"): OS COPS driver spins at `$520842-$52084E` sending command `$7C` (enable mouse interrupts, 16 ms — hardware-notes §4); our COPS drops CRDY on EVERY port-A write including reg-15 no-handshake peeks; the real protocol (§4 COPSCMD listing, LIBHW-DRIVERS:822-887): write cmd byte to IORA2, poll CRDY ready→not-ready on PORTB2 bit 6, flip DDRA2 $00→$FF around the data transfer, DDRA2 back to input. The ROM's own send path (M1b-established) also works via these semantics — but our current model's shortcut (reg-15 write drops CRDY) is what the ROM pins rely on. The rework must model CRDY as the OS expects (DDRA2-gated: CRDY reflects the 6504-side ready state; drops when a command is LATCHED — the DDRA2 output-flip being the latch signal per the listing — and re-raises after processing) while keeping every ROM-era pin green: menu FNV `0xd09234d25516d0b8`/78,100 px, POST markers, COPSTests, M1c input backstop, M2/M3 boot anchors (blocksRead 75, `$520000` entry). If a ROM pin legitimately moves under the corrected model, that's stop-the-line: investigate WHY (the ROM traces at M1b documented the actual poll sites — re-verify against them) before any re-anchor.
- Interrupt facts: SR has been $2700+ the entire boot; the OS WILL unmask (INITSYS installs vectors then the scheduler idles at lower IPL — SOURCE-STARTUP/SCHED per the original evaluation). First live delivery = level 2 (COPS/VIA2) and level 1 (VIA1 T1 ms-tick — the OS's DriverInit programs T1 with $CA/$27 or $7B/$63 per board; our board-ID choices matter here) — watch delay-vs-timeout semantics (twig_entry D2 timeouts, COPSCMD spin-waits) and fix with evidence.
- OQ1″ capture protocol: at the first user-process launch (scheduler → Launch → RTE to user mode), if supervisor code then accesses user-domain addresses (syscall buffer copies — EXCEPASM's domvalue machinery), capture PC/SR/domain-latch/address-class and the OS-source expectation BEFORE changing Bus.translationDomain; the resolution gets the same evidence bar as OQ1′.
- Honest exit bar: the OS running its scheduler with at least its first process launched — OR the desktop itself — OR a documented genuinely-new-subsystem boundary (Widget probe for the boot volume is PLAUSIBLE: the install environment may insist on probing the parallel port/internal drive — if so, THAT is the boundary and M5 = Widget). Floppy writes: implement session-scoped write-through the moment the OS writes (it will, eventually — swap lives on the boot volume).
